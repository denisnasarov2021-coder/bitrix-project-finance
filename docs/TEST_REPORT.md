## Какие риски проверены

1. Точный ввод копеек; сумма 0,10 + 0,20 даёт 0,30.
2. Запрет нулевых, отрицательных, слишком больших сумм и дробей более двух знаков.
3. Отдельная интерпретация дивидендов и расчёт прибыли до/после них.
4. Пустой проект, нулевой доход, убыточный проект, исключение удалённых строк.
5. Рентабельность портфеля считается по суммам, без усреднения процентов проектов.
6. Реальные календарные даты, високосный год и невозможные даты.
7. Повторный визит не создаёт демоданные заново.
8. Наблюдатель не может записать данные прямым API-запросом.
9. Чужой проект недоступен для чтения истории и записи.
10. Создание проекта, назначение автора руководителем, собственные статьи, запрет дублей.
11. Два одновременных одинаковых POST создают одну операцию и одно событие аудита.
12. Два одновременных UPDATE одной версии: один успех и один конфликт 409.
13. Мягкое удаление меняет итоговые суммы и сохраняет автора/след удаления.
14. Добавление и отзыв доступа участника; запрет удаления своей роли.
15. CHECK-ограничения D1 действуют при записи в обход API; чужой Origin и ошибочный JSON отклоняются.
16. Рабочий режим требует токен; клиентские user ID/domain/admin/demo header не дают доступа к другому пространству.
17. Собранный Worker возвращает HTML приложения на русском и корректный POST→303 при открытии из Битрикс24. Токены не переносятся в URL.

## Найденные и исправленные ошибки

| Ошибка | Как обнаружена | Исправление |
|---|---|---|
| Незакрытые JSX-фрагменты у кнопок действий | TypeScript | Исправлены закрывающие элементы |
| Несовместимая дата Cloudflare runtime | Первый запуск Miniflare | Зафиксирована поддерживаемая дата 2026-05-01 |
| Счётчик изменённых строк включал запись триггера аудита и создавал ложный 409 | Тесты параллельных UPDATE и удаления | Успех определяется через `UPDATE ... RETURNING`, затем повторно выполнены тесты |
| Пример D1 из стартового шаблона ссылался на неиспользуемый helper | TypeScript | Удалены неиспользуемые примеры; API использует свой типизированный слой запросов |

## Что не проверено

- Реальная установка, SDK-обмен iframe и обновление токена на портале Битрикс24.
- Реальные политики приложения, ограничения тарифа и учётные записи работодателя.
- Визуальная проверка кликами в браузере, screen reader и испытание на мобильных устройствах.
- Нагрузочное тестирование, большой объём данных и внешнее развёртывание в личном аккаунте Cloudflare.

Адаптер Битрикс24 тестируется с контролируемым ответом REST. Это доказывает логику проверки пользователя и ограничение домена, но не подтверждает успешную установку на конкретном портале. Перед сдачей следует пройти демонстрационный сценарий из README и отдельную приёмку из BITRIX24.md.
